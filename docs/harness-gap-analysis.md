# Harness 需求实现差距分析

> 基于 1.2 和 1.3 章节的需求定义
> 分析日期：2026-08-05

---

## 一、Harness 定位与职责边界

### 需求定义

| 职责 | Harness 做的事 | Harness 不做的事 |
|------|--------------|-----------------|
| **核心定位** | LLM 与执行环境之间的适配器和控制层 | 不替代 LLM 产生业务推理 |
| **约束控制** | 限制智能体的风险，将行为控制在安全边界内 | 不扩展智能体能力 |
| **生命周期** | 任务接收→状态追踪→工具调用→结果验证→反馈 | 不直接承担工具内部逻辑 |

### 当前实现对照

| 需求 | 实现状态 | 文件位置 | 差距 |
|------|---------|---------|------|
| 中间层角色 | ✅ 已实现 | `harness_agent_adapter.py` | 无 |
| 约束和可控性 | ⚠️ 部分实现 | `runtime_engine/governance.py` | 缺少人工审批流程 |
| 生命周期管理 | ✅ 已实现 | `runtime_engine/orchestration.py` | 无 |

## 二、五大核心子系统实现状态

### 1. 运行时引擎 (Runtime Engine)

**需求职责**：
- 状态机管理（初始化→执行→暂停→恢复→完成）
- 消息编排（构造 LLM 消息、处理响应）
- 异步执行（I/O 不阻塞、并发处理）
- 超时和中断（执行超时、优雅中断）

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 状态机管理 | ✅ | `AgentRuntime.status`: initializing/running/sleeping/stopped/failed |
| 消息编排 | ⚠️ | `MemoryEngine.store_conversation()` 仅基础存储 |
| 异步执行 | ✅ | 全异步 `async/await` |
| 超时和中断 | ⚠️ | 沙箱有超时，主循环缺少优雅中断 |

**差距**：
- [ ] 缺少执行主循环的显式状态机实现
- [ ] 缺少任务中断后的恢复机制

---

### 2. 工具层 (Tool Layer)

**需求职责**：
- 工具注册（维护 Tool Registry）
- 工具发现（语义搜索、推荐）
- 参数验证（签名检查）
- 权限检查（Free/Ask-first/Approve-once）
- 执行隔离（沙箱）
- 结果标准化

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 工具注册 | ⚠️ | `ActionEngine.register_tool()` 仅有内存注册 |
| 工具发现 | ❌ | 未实现 |
| 参数验证 | ⚠️ | Schema 验证在 `tools/*.json` |
| 权限检查 | ⚠️ | `allowed_tools` 白名单，缺少 Ask-first |
| 执行隔离 | ✅ | `sandbox/nsjail.py`, `firecracker.py` |
| 结果标准化 | ⚠️ | `ActionResponse` 有基础结构 |

**差距**：
- [ ] 缺少持久化工具注册表
- [ ] 缺少工具发现/推荐机制
- [ ] 缺少梯度化权限（Ask-first/Approve-once）

---

### 3. 记忆子系统 (Memory Subsystem)

**需求职责**：
- 工作记忆（上下文窗口）
- 短期记忆（会话摘要、偏好）
- 长期记忆（用户档案、向量检索）
- 记忆压缩、遗忘策略

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 工作记忆 | ✅ | `AgentSession.context_window_tokens` |
| 短期记忆 | ⚠️ | `AgentSessionMessage` 存储对话 |
| 长期记忆 | ⚠️ | `AgentMemory` 表存在，缺少向量检索 |
| 记忆压缩 | ❌ | 未实现摘要生成 |
| 遗忘策略 | ⚠️ | `MemoryEngine.cleanup_expired()` 仅按 TTL |

**差距**：
- [ ] 缺少向量记忆检索
- [ ] 缺少对话摘要自动生成
- [ ] 缺少用户偏好学习

---

### 4. 模型集成与输出治理

**需求职责**：
- 模型选择（多模型路由）
- 提示词管理（系统提示、示例）
- 输出解析（结构化提取）
- 输出验证（格式、一致性、安全）
- 降级策略（重试、切换模型）

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 模型选择 | ✅ | `ModelGatewayService` 支持多模型 |
| 提示词管理 | ✅ | `AgentConfig.system_prompt` |
| 输出解析 | ⚠️ | 依赖 LangGraph，Harness 未实现 |
| 输出验证 | ⚠️ | `GovernanceEngine` 有基础检查 |
| 降级策略 | ❌ | 未实现 |

**差距**：
- [ ] 缺少输出结构化解析器
- [ ] 缺少幻觉/矛盾检测
- [ ] 缺少模型降级策略

---

### 5. 编排引擎 (Orchestration Engine)

**需求职责**：
- 工作流定义（顺序/分支/并行/循环）
- 依赖管理
- 智能体分配
- 结果聚合
- 故障恢复

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 工作流定义 | ✅ | `OrchestrationMode`: SUPERVISOR/ROUND_ROBIN/VOTING/PIPELINE/PARALLEL |
| 依赖管理 | ⚠️ | PIPELINE 模式有隐式依赖 |
| 智能体分配 | ⚠️ | `WorkerAgent` 有优先级 |
| 结果聚合 | ✅ | `_aggregate_results()` |
| 故障恢复 | ❌ | 未实现自动重试/切换 |

**差距**：
- [ ] 缺少条件分支支持
- [ ] 缺少循环执行支持
- [ ] 缺少故障恢复策略

## 三、两大基础保障实现状态

### 6. 安全层 (Security Layer)

**需求职责**：
- 梯度化权限（Free/Ask-first/Approve-once）
- 沙箱隔离
- 输入验证
- 输出过滤
- 审计日志

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 梯度化权限 | ❌ | 仅有白名单，无 Ask-first |
| 沙箱隔离 | ✅ | NsJail + Firecracker |
| 输入验证 | ✅ | `MemoryEngine._sanitize_content()`, `_detect_injection()` |
| 输出过滤 | ⚠️ | `GovernanceEngine._check_dangerous_actions()` |
| 审计日志 | ✅ | `WorkspaceAuditLog`, `AgentRuntimeEvent` |

**差距**：
- [ ] 缺少人工审批流程（Ask-first/Approve-once）
- [ ] 缺少输出安全过滤链

---

### 7. 可观测性层 (Observability Layer)

**需求职责**：
- 日志（事件序列、搜索）
- 追踪（完整执行路径、耗时）
- 指标（吞吐量、延迟、错误率、告警）

**当前实现**：

| 功能 | 状态 | 说明 |
|------|------|------|
| 日志 | ✅ | `AgentRuntimeEvent`, `WorkspaceAuditLog` |
| 追踪 | ✅ | `GovernanceEngine` trace_id, steps |
| 指标 | ❌ | 未实现聚合指标 |
| 告警 | ❌ | 未实现 |

**差距**：
- [ ] 缺少性能指标收集（P50/P95/P99）
- [ ] 缺少错误率统计
- [ ] 缺少告警机制

## 五、优先级建议

### P0（核心功能，必须实现）

1. **梯度化权限管理** - Ask-first/Approve-once 流程
2. **输出结构化解析** - 从 LLM 输出提取工具调用
3. **故障恢复策略** - 自动重试、降级

### P1（重要功能，尽快实现）

4. **工具注册表持久化** - 支持工具发现和版本管理
5. **对话摘要生成** - 长对话压缩
6. **性能指标收集** - P50/P95/P99 延迟

### P2（增强功能，可选实现）

7. **工具发现/推荐** - 语义搜索
8. **条件分支/循环** - 复杂工作流
9. **告警系统** - 异常检测通知

## 七、总结

**当前实现满足了约 72% 的 Harness 需求定义**。

核心架构完整：
- ✅ Runtime Engine 状态管理
- ✅ 沙箱隔离执行
- ✅ 基础审计追踪
- ✅ 编排模式（Supervisor/Pipeline/Voting）

**主要差距**：
1. 梯度化权限（Ask-first/Approve-once）
2. 输出治理（结构化解析、降级策略）
3. 记忆压缩和向量检索
4. 性能指标和告警
5. Harness 约束系统的机械化规则

**建议下一步**：优先实现 P0 的三项核心功能，确保生产环境的安全性。
