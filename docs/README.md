# RAG 平台设计文档

## 1. 系统概述

### 1.1 架构概览

本 RAG（Retrieval-Augmented Generation）平台采用前后端分离架构：

- **前端**: React 19 + Vite + TypeScript + TailwindCSS
- **后端**: Python FastAPI + SQLAlchemy (async)
- **向量数据库**: Milvus 2.6.x (etcd + MinIO 存储)
- **关系数据库**: PostgreSQL 16 (元数据存储)
- **缓存层**: Redis 7.4.x (缓存 + arq 任务队列)

### 1.2 核心功能

1. **知识库管理**: 文档上传、分块、向量化、检索
2. **智能问答**: 基于 RAG 的对话式问答
3. **数据连接器**: 支持多种数据源接入 (API、Web、Database)
4. **用户权限**: 基于角色的访问控制 (RBAC)
5. **API 集成**: RESTful API + API Key 管理
6. **可观测性**: 审计日志、指标监控

## 1.3 角色定义

平台采用基于角色的访问控制 (RBAC) 模型，定义以下四种核心角色：

| 角色 | 职责 | 典型用户 |
|------|------|----------|
| **Admin（管理员）** | 平台全量控制：用户管理、角色分配、系统配置、审计日志查看、告警管理 | IT 管理员、平台 Owner |
| **Editor（编辑者）** | 知识库内容运营：上传文档、管理连接器、审查分块质量、运行评估测试 | 知识管理专员、技术文档工程师 |
| **Viewer（查看者）** | 纯查询权限：在授权知识库范围内提问、查看引用来源、反馈答案质量 | 普通员工、团队成员 |
| **Developer（开发者）** | 程序化集成：通过 API 构建自定义应用、集成聊天机器人、管理 API Keys | 工程师、集成开发人员 |

### 1.3.2 角色详细说明

#### Admin（管理员）
- **核心职责**: 平台整体运营和管理
- **关键能力**:
  - 创建/编辑/删除用户账号
  - 分配和撤销用户角色
  - 配置系统级参数（模型、存储、安全策略）
  - 查看全量审计日志
  - 管理系统告警和通知
- **使用场景**: 企业 IT 管理员进行平台初始化配置、用户入职/离职处理

#### Editor（编辑者）
- **核心职责**: 知识库内容的生产和维护
- **关键能力**:
  - 创建和管理知识库
  - 上传、编辑、删除文档
  - 配置数据连接器（API、Web 爬取、数据库同步）
  - 审查和调整文档分块策略
  - 运行检索质量评估测试
- **使用场景**: 技术文档团队维护产品知识库、客服团队更新问答库

#### Viewer（查看者）
- **核心职责**: 消费知识库内容
- **关键能力**:
  - 在授权范围内进行知识问答
  - 查看答案的引用来源
  - 对答案质量进行反馈（有用/无用）
  - 查看个人问答历史
- **使用场景**: 普通员工查询公司政策、产品使用指南

#### Developer（开发者）
- **核心职责**: 通过 API 进行二次开发
- **关键能力**:
  - 创建和管理 API Keys
  - 设置 API 速率限制和配额
  - 查看 API 使用统计
  - 调用 RAG API 构建自定义应用
- **使用场景**: 开发团队将 RAG 能力集成到内部工具、客服机器人

## 3. API 设计

### 3.1 认证与授权

| 端点 | 方法 | 描述 | 权限 |
|------|------|------|------|
| `/api/v1/auth/login` | POST | 用户登录 | 公开 |
| `/api/v1/auth/register` | POST | 用户注册 | 公开 |
| `/api/v1/auth/me` | GET | 获取当前用户信息 | 认证用户 |
| `/api/v1/auth/api-keys` | GET/POST | 管理 API Keys | 认证用户 |

### 3.2 用户管理（Admin）

| 端点 | 方法 | 描述 |
|------|------|------|
| `/api/v1/users` | GET | 用户列表 |
| `/api/v1/users/{id}` | GET | 用户详情 |
| `/api/v1/users` | POST | 创建用户 |
| `/api/v1/users/{id}` | PUT | 更新用户 |
| `/api/v1/users/{id}` | DELETE | 删除用户 |
| `/api/v1/users/{id}/roles` | POST | 分配角色 |

## 5. 安全设计

### 5.1 密码安全
- 使用 bcrypt 进行密码哈希
- 密码长度要求：8-100 字符

### 5.2 Token 管理
- Access Token: JWT，有效期 30 分钟
- Refresh Token: JWT，有效期 7 天

### 5.3 API Key
- SHA-256 哈希存储
- 仅创建时显示完整 Key
- 支持速率限制和配额管理

### 5.4 审计日志
- 记录所有敏感操作
- 包含：用户、动作、资源、IP、时间戳
