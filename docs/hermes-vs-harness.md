│  └─────────────────────────────────────────────────────┘    │
│                                                              │

│  │  4. 审计日志 (Audit Logging)                         │    │

## 5. 实际场景对比

### 场景 1: 代码生成任务

```
用户："帮我写一个 Python 脚本，分析 CSV 文件并生成图表"

┌─────────────────────────────────────────────────────────────┐
│  Hermes 的思考过程：                                         │
│  1. 读取用户记忆 → 了解用户偏好 (matplotlib 还是 seaborn?)   │
│  2. 任务分解 → 读取 CSV → 数据分析 → 生成图表 → 保存文件    │
│  3. 调用工具 → 执行 Python 代码                              │
│  4. 结果验证 → 检查图表是否正确生成                         │
│  5. 经验复盘 → 记住用户偏好，下次更高效                     │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  Harness 的检查过程：                                        │
│  1. 身份验证 → 用户是否有权执行代码？                       │
│  2. 资源配额 → 本次执行 CPU/内存是否超限？                  │
│  3. 沙箱准备 → 启动 Firecracker MicroVM                     │
│  4. 代码审查 → 是否有危险操作 (rm, eval, 网络请求)?         │
│  5. 执行监控 → 超时/资源超限则终止                          │
│  6. 输出审查 → 生成的文件是否合规？                         │
│  7. 审计记录 → 完整记录操作日志                             │
└─────────────────────────────────────────────────────────────┘
```

### 场景 2: 数据分析任务

```
用户："分析上个月的销售数据，找出趋势"

┌─────────────────────────────────────────────────────────────┐
│  Hermes:                                                    │
│  - 读取长期记忆 → 了解"上个月"定义、用户常用分析维度        │
│  - 主动规划 → 数据清洗 → 统计分析 → 可视化 → 洞察总结      │
│  - 调用工具 → 数据库查询、Python 分析、图表生成              │
│  - 经验固化 → 将分析模板存入记忆，下次复用                  │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  Harness:                                                   │
│  - 数据访问权限 → 用户是否有权访问销售数据？                │
│  - 查询限制 → SQL 是否包含危险操作 (DROP, DELETE)?          │
│  - 资源限制 → 大数据集处理是否超时/超内存？                 │
│  - 输出审查 → 是否包含敏感信息 (客户隐私)?                  │
│  - 审计日志 → 记录谁在什么时候访问了什么数据                │
└─────────────────────────────────────────────────────────────┘
```

## 7. 实现建议

### 7.1 如果你的平台需要...

| 需求 | 推荐方案 |
|------|---------|
| **自主完成任务的 AI** | Hermes (或类似 Agent 框架) |
| **安全的代码执行** | Harness (沙箱 + 审计) |
| **两者都要** | Hermes + Harness 联合架构 |
| **企业级部署** | Harness 优先，安全合规第一 |
| **个人助手** | Hermes 优先，个性化体验重要 |

### 7.2 技术选型

```
Hermes 类框架/平台:
├─ LangChain Agents
├─ AutoGen
├─ CrewAI
├─ 自研 Agent 框架
└─ (带记忆和规划能力的任何 Agent)

Harness 类框架/平台:
├─ E2B Sandbox (https://e2b.dev)
├─ Firecracker MicroVM
├─ gVisor
├─ nsjail
├─ Harness.io (DevOps 平台，有 AI 治理功能)
└─ 自研沙箱 + 审计系统
```

## 8. 总结

### 核心区别一句话

> **Hermes 让 AI 更聪明，Harness 让 AI 更靠谱。**

### 最佳实践

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   聪明的 AI (Hermes) + 靠谱的约束 (Harness) = 可信赖的 AI    │
│                                                             │
│   · 让 Hermes 发挥创造力，主动完成任务                      │
│   · 让 Harness 划定边界，确保安全合规                       │
│   · 两者结合 = 既强大又可信赖的 AI 平台                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
