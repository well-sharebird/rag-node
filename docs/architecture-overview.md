## 二、核心业务逻辑

### 2.1 Agent 执行流程

```
用户请求
   │
   ▼
┌─────────────────────────────────────────┐
│  API: POST /api/v1/agents/{id}/execute  │
└─────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────┐
│  AgentService.execute()                 │
│  - 加载 Agent 配置                        │
│  - 初始化上下文                          │
│  - 选择执行模式 (SINGLE/MULTI/META)     │
└─────────────────────────────────────────┘
   │
   ├─────────────────┬──────────────────┐
   ▼                 ▼                  ▼
┌─────────┐   ┌───────────┐   ┌─────────────┐
│ LangGraph│   │Harness    │   │Meta Agent   │
│ Engine   │   │Adapter    │   │Service      │
└─────────┘   └───────────┘   └─────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│  TAO 循环引擎                              │
│  ┌─────────────────────────────────┐    │
│  │  Think: 调用 LLM 生成推理和计划     │    │
│  │   ↓                              │    │
│  │  Act: 权限检查 → 工具执行         │    │
│  │   ↓                              │    │

│  │   ↓                              │    │

│  │   - 工具调用耗尽？→ COMPLETED     │    │
│  │   - 最大轮数？→ FAILED            │    │
│  │   - Token 耗尽？→ FAILED          │    │
│  │   - 用户取消？→ INTERRUPTED       │    │
│  │   - 超时？→ FAILED                │    │
│  │   - 目标达成？→ COMPLETED         │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────┐
│  流式返回结果 (SSE)                      │
│  - 推理过程                             │
│  - 工具调用                             │
│  - 最终答案                             │
└─────────────────────────────────────────┘
```

## 六、关键设计决策

### 6.1 Harness 定位

**决策**: Harness 是约束系统，不是执行引擎。

**理由**:
- 约束应该文档化、机械化、可验证
- 执行引擎可插拔（LangGraph 或 Runtime Engine）
- 约束层定义"什么不能做"，引擎层负责"怎么做"

---

### 6.2 双引擎策略

**LangGraph**: 适合预定义流程、可视化编排

**Runtime Engine**: 适合动态任务、长程对话、TAO 循环

两者共存，通过 `HarnessAgentAdapter` 适配。

---

### 6.3 梯度化权限

**FREE** → 直接执行（低风险工具）

**ASK_FIRST** → 首次询问，批准后缓存（中风险）

**APPROVE_ONCE** → 每次审批（高风险）

---

### 6.4 TAO 循环终止条件

1. **工具调用耗尽** - 无工具调用 + 有最终答案 → COMPLETED
2. **最大轮数** - 达到 max_iterations → FAILED
3. **Token 耗尽** - 超出 95% 预算 → FAILED
4. **用户取消** - user_cancelled=True → INTERRUPTED
5. **超时** - elapsed >= timeout → FAILED
6. **目标达成** - goal_achieved=True → COMPLETED
7. **停止标记** - stop_signal=True → FAILED

## 九、总结

**架构核心**: Harness 约束层 + Runtime Engine 执行引擎

**业务主线**: Agent 配置 → Runtime 创建 → Session 执行 → TAO 循环 → 结果返回

**关键特性**:
- 梯度化权限管理
- 多格式输出解析
- TAO 循环引擎
- 7 种终止条件
- Token 预算管理
- 沙箱隔离执行

**生产就绪度**: 核心功能完整，建议继续完善 P1 功能（工具注册表、向量记忆、性能指标）。
