## 核心组件清单

### 1. TAO 循环引擎 (心脏)

**文件**: `runtime_engine/agent_loop.py`

**职责**: 驱动智能体的思考 - 行动 - 观察循环

| 功能 | 实现状态 | 说明 |
|------|---------|------|
| 思考阶段 | ✅ | 调用 LLM 生成推理和行动计划 |
| 行动阶段 | ✅ | 调用工具执行，流式处理 |
| 观察阶段 | ✅ | 处理执行结果，决定下一步 |
| 流式输出 | ✅ | 事件驱动，实时反馈 |
| 错误恢复 | ✅ | 超时/预算耗尽/中断处理 |
| 事件发射 | ✅ | 每个阶段发射事件 |

**核心循环**:
```
Think → Act → Observe → (循环直到任务完成或失败)
```

**文件**: `runtime_engine/orchestration.py`

**职责**: 多 Agent 协作与任务分发

| Supervisor 模式 | ✅ | 主管分配任务给 Worker |
| Round Robin 模式 | ✅ | 轮流处理 |
| Voting 模式 | ✅ | 投票决策 |
| Pipeline 模式 | ✅ | 顺序流水线 |
| Parallel 模式 | ✅ | 并行执行 |
| 故障恢复 (P0) | ✅ | 重试策略、降级切换 |

**重试策略**:
- `NONE` - 不重试

## 关键设计决策

### 1. Harness 不是执行引擎

**决策**: 将 `harness/` 重命名为 `runtime_engine/`，真正的 Harness 约束系统在 `.agents/` 和 `.harness/` 目录。

**理由**: 
- Harness 本质是约束系统，不是执行引擎
- 约束应该文档化、机械化、可验证
- 执行引擎可插拔（LangGraph 或 Runtime Engine）

### 2. TAO 循环作为心脏

**决策**: 实现 `AgentLoopEngine` 作为核心执行循环。

**理由**:
- 思考 - 行动 - 观察是 Agent 的基本模式
- 循环设计比链式设计更具适应性
- 支持流式处理和事件驱动

### 3. 梯度化权限

**决策**: 实现 FREE / ASK_FIRST / APPROVE_ONCE 三级权限。

**理由**:
- 不同风险操作需要不同审批级别
- 缓存已批准的权限避免重复询问
- 风险等级决定过期时间

### 4. 输出结构化解析

**决策**: 实现多格式解析器（JSON/函数/XML）。

**理由**:
- LLM 输出格式不固定
- 需要可靠提取工具调用
- 支持 Schema 验证

### 5. Token 预算管理

**决策**: 实现多种压缩策略（截断/摘要/滑动窗口）。

**理由**:
- 上下文窗口有限
- 长对话需要压缩
- 不同场景需要不同策略

## 与 LangGraph 的关系

```
┌─────────────────────────────────────────────────────────────┐
│                    Harness 约束层                             │
│  (定义什么不能做)                                            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              执行引擎 (可插拔)                               │
│  ┌─────────────────┐         ┌─────────────────────────┐   │
│  │  LangGraph      │   或    │  Runtime Engine         │   │
│  │  (状态图驱动)    │         │  (TAO 循环驱动)          │   │
│  └─────────────────┘         └─────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**Runtime Engine 不是替代 LangGraph，而是提供另一种执行选择**:
- LangGraph: 适合预定义流程、可视化编排
- Runtime Engine: 适合动态任务、长程对话

## 总结

**Harness 本质**: LLM 与真实执行环境之间的系统工程框架

**核心目标**: 不是扩展能力，而是约束风险

**实现状态**: 84% 需求覆盖，P0 核心功能完整

**架构完整性**:
- ✅ 约束层（Harness 范式）
- ✅ 执行引擎（TAO 循环）
- ✅ 四层能力（编排/记忆/行动/管控）
- ✅ 基础保障（权限/解析/预算）

**生产就绪度**: 核心功能可用，建议完成 P1 增强后大规模部署。
