## 一、产品概述

### 1.1 产品定位

Agent 平台是一个企业级智能体开发与运行平台，基于 RAG(检索增强生成) 架构，提供：
- **智能体创建**: 可视化配置智能体，无需编码
- **智能体执行**: 支持单智能体、多智能体协作、Meta Agent 自主决策
- **知识集成**: 无缝对接企业知识库，提供 RAG 检索增强
- **安全管控**: 完整的权限管理、审计日志、沙箱隔离

### 1.2 目标用户

| 用户角色 | 需求场景 | 核心功能 |
|----------|----------|----------|
| **Admin** | 平台管理 | 用户管理、角色分配、系统配置、审计日志 |
| **Editor** | 知识运营 | 智能体创建、知识库管理、分块质量审查 |
| **Viewer** | 终端用户 | 在授权范围内提问、查看引用、反馈质量 |
| **Developer** | 集成开发 | API 调用、自定义应用、聊天机器人集成 |

### 1.3 核心价值

1. **降低 AI 使用门槛**: 可视化配置，业务人员可创建专业智能体
2. **提高答案准确性**: RAG 检索增强，基于企业知识库回答
3. **保障数据安全**: 沙箱隔离、权限控制、完整审计
4. **支持复杂任务**: 多智能体协作，处理复杂工作流

### 5.1 智能体管理

```
GET    /api/v1/agents/{id}         # 智能体详情
PUT    /api/v1/agents/{id}         # 更新智能体
DELETE /api/v1/agents/{id}         # 删除智能体

POST   /api/v1/agents/{id}/publish     # 发布
POST   /api/v1/agents/{id}/unpublish   # 取消发布
POST   /api/v1/agents/{id}/duplicate   # 复制
GET    /api/v1/agents/public           # 广场列表
```

### 5.2 智能体执行

**Harness 架构采用统一入口**，用户无需关心底层是普通 Agent 还是 Meta Agent：

```
POST   /api/v1/agents/execute           # 非流式执行 (统一入口)
POST   /api/v1/agents/execute/stream    # 流式执行 (SSE, 统一入口)
```

**请求参数**：
```python
class ExecuteRequest(BaseModel):
    query: str                    # 用户问题/指令
    agent_id: Optional[str] = None  # 可选：指定 Agent ID
                                    # 不传时由 Harness 自主决策
    
    # 可选参数
    kb_ids: Optional[list[str]] = None
    top_k: int = 5
    model_name: Optional[str] = None
    session_id: Optional[str] = None  # 会话 ID (用于记忆)
```

**Harness 内部决策逻辑**：
| 用户输入 | Harness 决策 |
|----------|--------------|
| "你可以做什么？" | 直接用 LLM 回答 (无需特定 Agent) |
| "帮我写个 Python 脚本" | 调用代码助手 Agent |
| "分析这个项目的架构" | 创建临时多 Agent 协作 |
| 已选择某个 Agent 后提问 | 使用指定的 Agent |

> **设计原则**：用户只需表达需求，Harness 负责选择最优执行策略。

**向后兼容**：保留 `/api/v1/agents/{id}/execute` 用于明确指定 Agent 的场景。

## 十、运行时引擎 (Runtime Engine)

> **运行时引擎是整个 Harness 系统的心脏**
>
> 如果说架构与原理是智能体系统的"骨架"，那么运行时引擎就是"血液循环系统"——它驱动智能体的每一个思考、决策、行动的周期，协调组件间的协作，管理系统资源的分配，处理边界情况与故障恢复。
>
> 在传统的编译原理中，运行时执行程序的代码并管理其生命周期；在 AI 智能体系统中，运行时执行智能体的一轮轮推理与行动循环，并管理整个会话的生命周期。

### 10.1 核心职责

| 职责 | 说明 | 实现文件 |
|------|------|----------|
| **智能体循环** | 执行 TAO(Think-Act-Observe) 循环，驱动自主推理与行动 | `runtime_engine/tao_graph.py` |
| **状态管理** | 管理会话状态快照，支持时间旅行调试与中断恢复 | `runtime/agent_runtime.py` |
| **流式处理** | 实时流式输出 token，优化用户体验 | `runtime/agent_runtime.py → execute_stream()` |
| **资源管理** | Token 预算、执行超时、重试策略 | `runtime_engine/token_budget.py` |
| **持久化** | Checkpoint 保存，支持中断后恢复 | `services/agent_checkpoint_service.py` |

### 10.2 TAO 循环架构

**智能体循环（Agent Loop）**是智能体系统的核心执行模式。经典的**"思考 - 行动 - 观察"(Think-Act-Observe)**循环定义如下：

| 阶段 | 职责 | 实现 |
|------|------|------|
| **思考 (Think)** | Agent 基于当前上下文（历史、状态、工具信息）进行推理，生成意图和下一步行动计划 | `runtime_engine/tao_graph.py → create_think_node()` |
| **行动 (Act)** | 模型发出工具调用意图，运行时验证、调度并由工具层执行，必要时改变外部世界状态 | `runtime_engine/tao_graph.py → ToolNode` |
| **观察 (Observe)** | Agent 获得运行时返回的工具执行结果，更新内部认知模型，为下一轮思考做准备 | `runtime_engine/tao_graph.py → create_observe_node()` |

**错误处理**：如果工具调用失败或返回意外结果，观察阶段会将其作为"负面证据"反馈给思考模块，触发错误恢复或备选方案。

**循环流程图**：
```
┌─────────────────────────────────────────────────────────────────────────┐
│                    图 10-1：思考 - 行动 - 观察循环                        │
│                                                                         │
│    ┌─────────────┐                                                      │
│    │   思考      │  ← 基于上下文推理，生成行动计划                       │
│    │   (Think)   │                                                      │
│    └──────┬──────┘                                                      │
│           │                                                             │
│           │ 工具调用意图                                                 │
│           ▼                                                             │
│    ┌─────────────┐                                                      │
│    │   行动      │  ← 运行时验证 → 工具执行 → 改变状态                   │
│    │   (Act)     │                                                      │
│    └──────┬──────┘                                                      │
│           │                                                             │
│           │ 执行结果/错误                                                │
│           ▼                                                             │
│    ┌─────────────┐                                                      │
│    │   观察      │  ← 更新认知模型，反馈给下一轮思考                     │
│    │   (Observe) │                                                      │
│    └──────┬──────┘                                                      │
│           │                                                             │
│           └──────────────┐                                              │
│                          │ (循环)                                        │
│                          ▼                                              │
│                     (回到思考)                                           │
└─────────────────────────────────────────────────────────────────────────┘
```

**为什么是循环而不是链？**

传统的**链式智能体**(Chain-of-Thought) 将思考和行动分开，形如：`提示 → 思考 → 规划 → 工具调用 → 输出`。这种设计的缺点是：

| 问题 | 说明 | 循环设计的解决方案 |
|------|------|-------------------|
| **缺乏适应性** | 一旦执行遇到问题（工具调用失败、输出超限），难以动态调整策略 | 每个循环迭代可获得反馈，动态调整策略 |
| **低效率** | 规划阶段必须预测所有可能的工具调用，容易过度规划或不足规划 | 逐步细化目标，按需调用工具 |
| **不可恢复** | 一旦规划失败，需要重新启动整个流程 | 错误作为负面证据反馈，触发恢复机制 |

**循环设计**允许智能体逐步细化目标，在每个循环迭代中获得反馈，动态调整策略。这更符合人类解决问题的过程。

**工程实现（LangGraph StateGraph）**：
```
┌─────────────────────────────────────────────────────────────────────────┐
│                         TAO 循环 (LangGraph StateGraph)                  │
│                                                                         │
│  START                                                                  │
│    │                                                                    │
│    ▼                                                                    │
│  ┌─────────────┐                                                        │
│  │   THINK     │ ← LLM 推理，生成行动计划与工具调用                       │
│  │   Node      │                                                        │
│  └──────┬──────┘                                                        │
│         │                                                               │
│         ▼                                                               │
│    ┌────────┐                                                           │
│    │ 有工具调用？│ ← 条件边路由 (should_act)                              │
│    └───┬────┘                                                           │
│        │                                                                │
│        ├───────────────┐                                                │
│        │               │                                                │
│        ▼               ▼                                                │
│   ┌────────┐      ┌────────┐                                            │
│   │  ACT   │      │  END   │                                            │
│   │ ToolNode│      │ (结束) │                                            │
│   └───┬────┘      └────────┘                                            │
│       │                                                                 │
│       ▼                                                                 │
│   ┌────────────┐                                                        │
│   │  OBSERVE   │ ← 处理工具执行结果，准备下一轮推理                       │
│   │   Node     │                                                        │
│   └─────┬──────┘                                                        │
│         │                                                               │
│         └──────────────┐                                                │
│                        │ (自环，回到 THINK)                              │
│                        ▼                                                │
│                   (循环继续)                                            │
└─────────────────────────────────────────────────────────────────────────┘
```

**终止条件**:
1. **无工具调用** - LLM 给出最终答案，无需进一步行动
2. **达到最大迭代次数** - 防止无限循环 (默认 10 轮)
3. **Token 预算耗尽** - 超出预算限制
4. **用户取消** - 外部中断信号
5. **超时** - 执行超过配置时长

### 10.3 状态管理

```python
# runtime/agent_runtime.py
class AgentRuntime:
    """
    Agent 运行时 - 统一执行入口

    核心能力:
    1. execute() - 批量执行
    2. execute_stream() - 流式执行
    3. interrupt() - 人机协作中断
    4. resume() - 恢复中断
    5. get_state() - 状态快照 (时间旅行)
    6. patch_state() - 修补状态 (时间旅行修改)
    """
```

**状态维度**:
| 维度 | 说明 | 隔离级别 |
|------|------|----------|
| `thread_id` | 线程 ID | 用户 × 会话 |
| `run_id` | 运行 ID | 单次执行 |
| `checkpoint` | 检查点 | 节点级别 |

### 10.4 资源配置

```python
# runtime/config.py
class RuntimeConfig(BaseModel):
    """运行时配置"""
    
    # 执行模式
    stream: bool = False                    # 流式输出
    recursion_limit: int = 50              # LangGraph 递归限制
    timeout_seconds: int = 300             # 执行超时
    
    # Token 预算
    token_budget: int = 4096               # 最大 Token 数
    reserve_tokens: int = 512              # 保留 Token (系统消息)
    
    # 检查点配置
    checkpointer: Literal["database", "memory", "none"] = "database"
    
    # 中断配置
    interrupt_before: Optional[list[str]] = None  # 节点前中断
    interrupt_after: Optional[list[str]] = None   # 节点后中断
    
    # 重试配置
    max_retries: int = 3                   # 最大重试次数
    retry_delay_seconds: float = 1.0       # 重试延迟
```

### 10.5 执行流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 1. API 层接收请求                                                        │
│    POST /api/v1/agents/{id}/execute/stream                              │
└─────────────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 2. HarnessEngine.execute()                                              │
│    - 加载系统提示词模板                                                  │
│    - 准备工具 (基础/MCP/技能/RAG)                                       │
│    - 构建 LangGraph StateGraph                                          │
└─────────────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 3. AgentRuntime.execute_stream()                                        │
│    - 构建 RunnableConfig (thread_id, run_id)                            │

└─────────────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 4. LangGraph 执行 TAO 循环                                                │
│    - THINK → LLM 推理                                                    │
│    - ACT → ToolNode 执行工具                                             │
│    - OBSERVE → 处理结果                                                  │

    ▼

```

### 10.6 性能指标

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 首 Token 延迟 (TTFT) | < 2s | 流式模式 |
| 完整响应延迟 | < 10s | 简单任务 |
| Token 生成速度 | ≥ 50 tokens/s | 流式输出 |
| 并发执行数 | ≥ 100 | 单节点 |
| 中断恢复延迟 | < 500ms | 从 Checkpoint 恢复 |
